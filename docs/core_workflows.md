# 当前核心任务与使用范围

Engineering 主入口近期聚焦三类只读任务。主页卡片先收集具体调查对象，再生成普通问题，进入已有 Conversation API、统一 Runtime 和证据校验流程。

**入口与对象取证切片已实现；核心任务整体可靠性仍未完全补齐。** Engineering按明确文件/定义或文件内匹配取得有界材料，每段保留真实定位与引用；填写对象能减少歧义，但不保证模型取得所有材料或完整答案正确。当前实测、负结果和剩余问题见 [2026-10-04 检查记录](validation/2026-10-04-core-workflows.md)。

| 任务 | 需要填写 | 希望取得的结果 | 当前边界 |
|---|---|---|---|
| 配置到行为追踪 | 一个配置名；已知源码路径或方法可选 | 实际默认值、覆盖与校验规则、消费参数的调用点及引用 | 优先调查一项配置及少量相关实现；未读常量或被调用方法仍可能遗漏 |
| 小范围变更与测试定位 | 一个有未提交变更的项目相对文件路径 | Git diff、行为影响、实际已有测试的输入/断言、建议命令 | 路径已给定时直接围绕该文件调查；静态读取不证明实际通过 |
| 文档与实现核对 | 文档路径和待核对内容；对应实现文件或方法 | 分别引用两边，区分一致、冲突与未核实 | 聚焦一项承诺；局部源码不能证明整个调用链一致或矛盾 |

## 操作

1. 按 [项目挂载手册](project_mount_runbook.md) 绑定本机已有项目，并确认 Engineering 可用。
2. 在新会话点击相应卡片。点击只选择任务，不会立即发送宽泛模板。
3. 填写调查对象，点击“开始调查”。缺少对象时提示补充；文档核对要求填写两边的目标。
4. 检查答案与 Evidence 中实际取得的材料。遇到“未核实”、拒答或只读到局部时，不应理解为任务全部完成。

仍可直接输入自由问题。三个入口没有专用放行条件，没有附加 Agent loop；同一个Reader在Engineering使用对象契约v4，legacy默认v2保留。多片段共享120行/8000正文字符、每段独立引用；预算仍为五次逻辑决策、四次工具调用、两次工具错误。

## 面试与展示口径

项目可以展示有证据的源码调查、变更分析和文档核对，以及持久化、SSE、受控工具调用和负实验处理。当前不承诺完整代码修复、执行测试、任意仓库问题均可回答或 claim-level 语义校验。

当前 `completed` 是 Runtime 的终止状态，不能代替任务正确性评审。展示时应同时说明读取了什么、实际完成了什么、哪些部分没有证据。
