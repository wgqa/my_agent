# 核心任务入口与对象取证（2026-10-04）

**入口和对象取证切片已交付；第一项整体可靠性仍未完全补齐。** 当前 Engineering 启用 Reader v4 与对应 decision v4：按明确文件/定义取得有界正文，连续来源各自引用。主页聚焦配置追踪、变更与测试定位、文档与实现核对。三项早期轻量候选均未启用；不扩大五次逻辑决策、四次工具调用、两次工具错误，不加按题放行 Guard，不启用长期 v2 契约。

## 改动与边界

- 主页卡片先收集目标，点击不会立即发送无对象模板；配置名、变更文件必填，文档核对需要两边目标。变更卡片明确文件已经给定，围绕该文件取得 diff 和相关测试。生成普通问题，经原 Conversation API/SSE 提交。
- 同一个 `read_project_context` 在 Engineering 注册 v4，legacy 默认 v2 保留。`path + target` 分别表达文件、行窗口、行内函数定义、最多四个具名 Python 定义或文件内 literal 匹配。具名目标返回真实限定名；短名存在多个定义时报告歧义，不任意选取。
- Python 只解析 AST，不 import/exec：取得函数/方法边界、装饰器和模块/类赋值定义；不求值、不自动解析导入或追踪整个依赖图。文件内匹配读取定义，避免把测试导入行作为测试正文。其他允许文本按 literal 定位前后30行并合并重叠窗口，能读到长文档后部。
- 一次只读一个允许文件，多个片段共享120行/8000正文字符上限，单行300字符。缺失、歧义、更多匹配、截断与续读位置公开。每个片段独立生成真实路径/连续行号的 E-ID，不能把不连续文本伪装成一个连续范围。
- Runtime 仅增加多片段来源转换；仍是原循环、七工具与5/4/2。API/schema、会话持久化、知识/Planner、访问检查和此前修复保留；Decision 新版本替换旧 Reader 参数说明，历史 prompt SHA/legacy 默认保持可用。没有目录大重构、额外模型、Jev 或目标项目的执行能力。

## 固定材料与审查方式

控制项目 Support Search 在独立本机 Git 副本中将默认值4改为6，文档和默认值测试仍为4；包括环境变量覆盖、范围校验、跨文件参数传递与简单词项计分。它是取证 fixture，不是另一个 RAG 产品。

Requests 固定于 `b25c87d7cb8d6a18a37fa12442b5f883f9e41741`。独立副本将 `Session.get_adapter` 的小写归一化比较改为直接比较，构成明确回归；原干净固定仓库未修改。只读源码，不安装或执行该仓库测试。真实 DeepSeek 使用既有 verified BM25 corpus `870e5864df67`，没有改模型或索引。

原六道开发题、后续六道核心题和两个边界控制先固定；后续新增问题、表单生成问题及修订复核分组记录。预设20请求先增加独立候选对照到32、表单三例到35；再声明对象取证14例、文本修订四例、变更入口修订一例，最终54。原catalog、修订快照与全部失败保留，没有自动付费任务重试。修订后的显式复核不是原版重复抽样或独立未见验收。

内容分数由同一开发助手核对固定源码、实际读取范围、引用、命令及完整答案；**不是独立验收，也不是项目总体成功率**。主体正确但带有未证实或错误附加结论记为 PARTIAL，completed不当作正确率。未使用 sealed Holdout。

## 仍然开放的问题

1. 已知路径有时仍被当成正文关键词搜索，测试取证也会反复猜改动常量名，四次调用耗尽后误拒答。新表单明确路径缓解一个例子，没有修复所有自由问题规划。
2. 引用和定义边界正确，仍不能保证整份答案语义受支持。Requests的混合大小写URL在本变更场景没有默认前缀匹配，应抛`InvalidSchema`；新答案仍说回退默认适配器。测试限定名与建议命令已正确，错误分支推断仍开放。
3. 配置答案把未读检索器的`limit`参数直接解释为返回条数上限；变更答案把单个测试文件中未见的断言概括为整体测试缺口。两者已明确记为PARTIAL，不因completed或主体正确而放行。
4. Planner仍可能把项目事实规划为独立技术知识检索，引入无关上下文。没有因此关闭知识库、叠加判定器或放松Verifier。

第一项保持OPEN。当前可展示的是有界对象取证、真实来源与负实验处理；任意仓库的稳定全面回答、自动修复/测试执行和claim-level语义校验仍不承诺。后续优先做一致的任务对象/来源规划或缩小回答范围，不能为上述URL、常量或测试名称继续加专用规则。
