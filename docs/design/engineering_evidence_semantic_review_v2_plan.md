## 1. 建议采用的方案

采用一个需求入口、一个工具执行循环，以及候选路径中的语义审查：

1. 需求 LLM 理解用户目标，提出所需对象、材料形态和范围。复用已经落地的 requirement provider 和冻结合同。
2. 程序从实际工具结果登记材料，保留正文、列表、定位、数值及其来源和完整性信息；每轮只更新程序进度。
3. 执行 Agent 提交答案或准备拒答时，审查 LLM 读取原问题、冻结需求、实际材料与本次提交，判断是否可以回答、需要补材料、需要修正答案或应当拒答。
4. 程序校验审查引用和可验证的硬条件，并执行受预算限制的下一步。候选路径不再使用旧类别/数量启发式作为语义终裁。

首期审查最多两次，不在每轮调用模型，不新增第二个 Agent 循环。旧规则和旧终结校验保留作对照；默认产品模式继续保持旧路径，直到真实对比支持切换。

这是一项有限的核心接口改造。知识 Planner、Knowledge Retrieval 协议、ToolExecutor 权限和原有 5 次 Decision / 4 次工具 / 2 次工具错误上限继续沿用。

## 3. 职责边界

| 角色 | 负责 | 不授予的职责 |
|---|---|---|
| 用户原请求 | 提供任务边界与最高验收依据 | 不被计划中的漏项或调查困难改写 |
| 需求 LLM | 识别目标、对象、材料深度、合理来源及能力边界 | 不给出成功证据 ID，不宣布已取得材料，不增加工具权限 |
| 执行 Agent | 选择现有工具、调查并生成候选答案 | 不自行签发完成状态，不伪造资料或重置预算 |
| 材料登记与硬检查 | 登记真实来源，检查 ID、对象、范围、已知截断、权限和预算 | 不用证据类别/数量代替自然语言支持关系 |
| 审查 LLM | 检查原问题覆盖、材料支持、答案完整性和拒答是否合理，给出具体缺项 | 不直接执行工具、不另写最终答案、不静默删除冻结目标 |

审查仍可能出错。程序只对能够证明的硬事实负责，模型负责语义判断，最终质量由独立 Gold 和人工复核评测。不能把模型批准宣传成答案已被数学证明正确。

## 4. 材料模型：少量形态与可组合属性

### 4.1 原子化到实际材料，不穷举业务结论

一个材料单元对应实际知识片段、Reader 区域、diff 片段或一份结构化工具结果。共同属性为来源、对象、形态、范围和完整性。最小字段含本轮材料 ID、实际调用/知识来源引用、工具及 schema 版本、项目绑定身份、实际内容或其引用、返回内容 hash、对象及范围、截断/完整性状态。

来源类别描述内容来自哪里；形态描述它是正文、列表、定位、数值还是绑定事实；语义目标由 LLM 解释。三者不再混成一种任务 profile。

需求阶段只组合“需要什么材料”，不能选择还不存在的 E-ID。审查阶段才能将实际 E-ID 绑定到目标。多种可替代来源与必须取得的多个对象分别表达，不误把 OR 当成 AND。

例如“比较 A、B 的缓存策略”需要两个对象的相关材料，由审查判断这些材料能否支持比较；不用注册“缓存策略比较证据”这种业务类型。模型总结或推断的结论仍是带来源的结论，不能重新登记成原始事实。

### 4.2 具体登记原则

| 来源 | 登记的材料形态 | 必须保留的边界 |
|---|---|---|
| Knowledge Retrieval | 实际知识片段与检索身份 | 当前来源、chunk/query 身份；不能自动当作仓库现状 |
| read_project_context | 返回的正文区域及目标信息 | 路径、定义、实际行段、content_complete、截断/歧义与 fallback |
| git_diff | 返回的差异片段 | 比较范围和可取得的 refs、实际内容、工具截断与公开投影截断 |
| code_search | 有范围的定位/候选集合 | 原查询、范围、返回命中及截断；命中不等于完整实现 |
| changed_files | 文件状态集合 | 请求比较范围、实际条目、total_count、returned_count、truncated、过滤计数 |
| find_tests | 测试候选集合 | 候选路径、匹配依据和范围；不能证明读过正文或执行通过 |
| calculator | 实际计算事实 | 实际表达式及返回数值 |
| get_project_info | 项目绑定事实或文档入口集合 | 当前绑定身份、可用状态；入口不等于项目用途正文 |

成功的空集合可以支持“本次范围内未找到”。失败 Observation 只进入诊断，不能当作空集合证据。列表还必须保留集合范围和完整性；逐条原子都真实不代表列表完整。

返回内容 hash 标识这一份返回快照，不冒称完整文件 hash 或完整仓库版本。去重包含内容身份，不仅按路径和行号去重；本轮记录互相隔离，不能用共享的 last_material/last_review 状态。首期不跨缺少可靠快照身份的调用拼接并签发“完整函数”，也不通过组合局部片段绕过 Reader 截断。若该能力成为实测主要缺口，另做版本化的 Reader 快照与范围拼接改造。

从已验证的 Observation 与既有检索结果建一个只读 MaterialLedger；复用现有材料的 E-ID，新增正式材料由程序统一分配编号。它是本轮交接结构，不是第二套数据库或执行系统。登记不额外读取文件、运行 Git、执行测试或发起隐藏工具调用。

装配时验证实际启用的工具均有版本明确的材料适配或显式“不产生取证材料”声明。遗漏适配属于实现/配置错误，不能静默忽略后给用户报证据不足。能力清单由实际 ToolSpec、禁用列表及材料适配生成，不按每道问题新增规则。

### 4.3 公开证据的最小扩展

保留旧 EngineeringEvidence 和 KnowledgeEvidence。候选路径增加一类 ToolResultEvidence，kind 为 tool_result，结果子类严格区分定位集合、变更列表、测试候选、计算事实、项目绑定/文档入口等。

这是“扩充证据类型”的一种数据实现，与原有类型并列，不额外再叠一套证据体系。payload 使用已登记工具的严格结构，不能成为任意 JSON 的通行证。没有正文的结果不带伪造行号；若定位有真实行号，仅展示真实命中位置。

内部 ledger 先完成；凡正式答案引用的新 E-ID，必须同时进入 API evidence、SSE evidence_added 和前端资料展示。不能完成了答案引用却只把来源藏在内部。前端仅补来源展示与缺项信息，保留 V2 stream，不重做页面或新增协议版本。对旧路径不注入新类型，不放宽旧类型的字段限制。

## 5. 需求与语义审查协议

### 5.1 需求分析

复用现有 RequirementGoal 的 deliverable、request_basis、source_kinds、depth、target 和 full_range，以及冻结输入/合同 hash。候选提示词加入真实能力清单并单独版本化；旧 v1 prompt 和 hash 保留。仅当字段协议确实变化时才升级需求 schema，不因增加审查就自动制造需求 V3。

候选完成控制不消费 required_evidence_groups 的旧形状投影作为终裁标准。规则兼容分支仍保留原 profile、组与路径数，不能人工补写旧规则没识别出的对象来提高对照成绩。

原请求与辅助历史继续分开。无效计划、超时或未知输出不降级成空目标。direct 是明确无需取证的任务，unsupported 是不能完成的任务，二者都可能没有来源要求，但必须有不同执行语义。混合请求逐目标处理，闲聊部分不能取消工程部分的材料要求。

首期 direct 可以零工具生成候选答案，仍通过提交审查确认原请求和答案没有被误当作无需取证的项目事实。免取证不等于遇到解析失败、能力不足或证据类型未知便放行。

### 5.2 末端审查

拟新增独立职责的 LLMCompletionReviewer，复用现有模型服务配置；不复用知识 Planner 的 QueryPlan。计划与审查可以使用同一模型服务，但各自有 prompt、schema、版本和计量。

输入包含：原请求与辅助指代、冻结需求、当前真实能力、只读材料快照、本次候选答案或拒答动作、剩余可用额度。必须传实际可见内容及完整性信息，不能只传标题或概括后的摘要。输入需要有总长度预算；未被审查模型看到的部分明确标记，不能默认为已验证。

输出采用严格 JSON：总体 decision、逐目标 verdict、支撑 E-ID、原请求覆盖状态、缺项类别、简短可公开反馈和合同问题。正常 decision 为 accept / need_material / revise_answer / refuse。模型不返回工具动作、权限、额度、新材料或代写答案；缺项建议交给执行 Agent 判断如何调查。

审查必须对照原问题检查漏目标、虚增目标和误判 direct。首期出现合同实质错误，记录 REQUIREMENT_CONTRACT_MISMATCH 并阻止 completed；不启动自动重新规划或隐式改合同。该项归入需求错误。后续若增加合同修订，需要另设版本、次数和归因，不藏在本阶段。

审查输出绑定原请求、contract、material_snapshot、submission 与 prompt 的 hash，并保存完整 review_input hash，覆盖能力/配置、输入裁剪和剩余额度。submission 包含动作类型及答案或拒答原因，不能仅 hash 一个可能为空的答案。程序校验目标与材料 ID 真正存在、模式一致、引用属于当前运行；对新材料或新答案不能复用旧批准。记录可重放不等于再次在线请求能得到相同审查结论。

accept 只批准 FinalAnswerAction 的实际答案。审查 RefuseAction 时，认可拒答输出 refuse；认为已有材料足够则输出 revise_answer，要求执行 Agent 在剩余 Decision 中先生成候选答案，再接受复审。审核模型不能将一个没有 answer 的拒答动作直接转成 completed。

### 5.3 程序硬检查与旧启发式分离

硬检查包括实际来源与数据类型、现有权限/预算、引用存在性、实际对象/范围，以及已明确要求完整材料时可证明的缺失或截断。自然语言是否被材料支持、是否真正回答原问题，交给审查模型并独立评测。

“已有一条 project_code”“有两个文件”“引用形式合法”不得代替语义批准。旧类别/数量判定只留在旧模式和明确的规则对照分支。候选模式不再叠加旧 G12 门槛作为另一位语义裁判。

知识 Planner 与 Retrieval 仍按原协议提供真实材料。需要知识来源的目标继续检查既有检索身份和覆盖；纯项目任务的偶然知识检索不新增工程验收目标；答案使用的知识引用仍检查真实性。不得为通过评测随意关闭知识校验。

## 6. 接入现有循环与有限恢复

将候选路径分成程序 progress() 与提交 review() 两个入口。旧 verify() 和 EngineeringVerificationResult 不变；新增版本明确的候选校验结果，独立包含程序检查、目标状态、模型审查和恢复类型。Runtime 显式选择策略和结果类型，不通过继承/伪装绕过旧结果的四项合取约束。

旧 ToolAgentRunResult 的证据类型约束保留；候选返回独立的 CandidateToolAgentRunResult。两者共用状态和预算不变量的检查，避免复制执行规则。Adapter、Facade、反馈与 stream 接受明确的结果分支；API 对未知候选类型显式报错，不能沿用仅匹配旧类型而静默漏掉来源的映射。候选结果只公开安全的策略/审查摘要，完整 ledger 和模型记录仍用于内部审查与评测。

每次 Decision 前只运行程序进度更新。首期仅在 FinalAnswerAction 或 RefuseAction 时调用语义审查，最多两次 API 尝试，不另设每轮模型审核或第三种卡住诊断触发器。审查不自动重试、不做隐藏 JSON 修复。修正提交复用剩余 Decision；即使工具额度为零，只要还有 Decision 和审查额度，也可修正已有材料的答案。可修复的引用/提交格式问题先由程序反馈，最多一次提交修正；没有调用模型的预检不计作审查 API，但仍消耗后续 Decision，不能获得无限免费改写。

| 审查/检查结果 | Runtime 行为 |
|---|---|
| 提交 FinalAnswerAction，硬检查合法，审查 accept，必需目标满足 | completed，发布该份已批准答案 |
| need_material，仍有合法取证、Decision 和复审机会 | 具体缺项反馈给原执行循环；不能重置额度 |
| revise_answer，仍有 Decision 和复审机会 | 原 Agent 修改答案或引用；最多一次修改机会 |
| refuse、确实不支持，或必要恢复机会耗尽 | refused，answer 保持 None，提供真实缺项/能力反馈 |
| 审查超时、服务错误、输出非法或内部计划合同错误 | failed，answer 保持 None，分别记录失败码 |
| 权限违规、伪造 ID、过期审查或已证明的范围违规 | 不放行；按可修复提交问题或不可恢复失败明确分类 |

模型判定 need_material 不是工具权限；程序仍检查下一步真实可行。拒答审查也可指出材料足够、应当生成答案，减少提前拒答。补材料的无进展检查依据材料和缺项变化；修改答案不能因为材料没变就被旧 fingerprint 规则提前拦截。重复调用与无进展保护继续保留。

新增需求/缺项描述走明确的候选任务上下文。它们作为数据传给 Decision，不放进可信 system 权限区，也不伪装成一次不存在的工具 Observation。沿用新版本 Decision prompt，替换旧“元数据永远不能成为 E-ID”等冲突语句；B/C/D 使用同一候选 prompt，旧 v7 不改。

审查调用与需求、Decision/格式修复分别计数，共享本请求合作式期限。保持现有 60 秒请求期限口径；审查起始设置为 temperature=0、每次 SDK timeout 最多 20 秒、输出最多 1600 token、最多两次尝试。ReviewInput 序列化总长起始上限为 60000 字符，在真实开发验证中检查可行性，正式评测前冻结。SDK timeout 还必须受实际剩余期限限制；SDK 自动重试为零，调用前后检查取消。输入超限或审查被截断分别记录 REVIEW_INPUT_LIMIT / REVIEW_OUTPUT_TRUNCATED，不裁掉材料后冒充全量审查。合作式期限不能宣传成能强制中断所有已在执行的同步调用。没有审查时间也不能跳过批准放行。

保留 completed/refused/failed 和非完成 answer=None 的协议；首期不新增 partial 状态。失败反馈只公开简短缺项与可行下一步，模型原始输出、凭据和隐藏思维过程不进入页面。

## 8. 验证与四组归因

### 8.1 必需的离线与产品用例

复用现有适用回归，补充有实际失效意义的用例：

1. A/B 多对象缺 B、错误文件、导入行、正文截断、未知完整范围均不得错误完成；不同内容的同路径材料不混并。
2. 定位、变更列表、测试候选、计算和绑定事实能进入正规材料与引用链；空结果可正确完成限定范围的查找任务。
3. 列表截断、过滤内容、仅搜索一部分目录，不能宣称全部或全仓不存在；测试候选不能证明测试通过。
4. direct 正确零工具回答；unsupported、混合任务、需求漏项、非法/空计划不借 direct 放行。
5. 材料充分但缺引用可以一次修正；提前拒答得到明确反馈；没有工具额度仍可修正提交；预算耗尽不扩大恢复机会。
6. reviewer 错误 ID、未知 goal、过期答案 hash、非法输出、超时、取消、重复复审和并发运行隔离都可观察且不放行。
7. 材料里的指令、伪造自证结论和审查建议不能变成可信权限；公开 API、V2 活动流、HTML 来源及非完成反馈兼容。
8. rule 默认零新增模型调用；shadow 不控制完成；不同策略装配拒绝非法组合，旧类型和旧输出保留。

固定 ReviewStub 证明程序接线与约束，不证明真实 LLM 审查正确。文档修改本身不需要重新跑整套业务测试；实施后按变更范围运行适用 CI 与前端检查。

### 8.2 真实实验组

| 组 | 需求实现 | 材料与完成策略 | 用途 |
|---|---|---|---|
| A | 当前冻结规则 | legacy 原类型/原完成逻辑 | 最新原路径对照 |
| B | 同一规则的无损兼容合同 | 候选材料＋程序结构检查，不调用语义 reviewer | 材料/执行接口改造的影响 |
| C | LLM，禁用规则回退 | 与 B 相同的候选基础设施与程序结构检查 | 需求替换的影响；B/C 兼容差异另报 |
| D | 与 C 同版本的 LLM，禁用规则回退 | 候选材料＋硬检查＋末端语义审查和有限反馈 | 本文推荐方案，与 C 比较新增审查的效果 |

B 不人工补出旧规则遗漏的具名目标，也不把列表映射成旧正文。规则合同和具名 LLM 目标不是完全同构，归因范围必须如实说明。C 是结构检查的实验对照，不作为已经实现语义验收的产品宣传。

各组冻结实际模型、参数、工具版本与启用集合、业务/项目/知识快照、预算、prompt 和期限口径。A 使用显式 rule provider，避免旧默认循环期限与候选全请求合作期限混为同一条件；原标签另用于历史行为重放。自然运行的 C/D 计划可能不同，要记录差异；补充固定计划/材料/提交的组件重放分析，不能将其冒充新端到端通过率或新调用成本。

先用已知 12 题做小规模真实开发验证（A/C/D 每题一次，共 36 次任务运行）。正式题集为既有 72 题和未参与实现调试的 24 新题，每组每题一次，共 384 次任务运行。再对 D 的固定 12 题额外重复两次，用于稳定性观察；保留所有结果，不择优。正式调用前另向用户告知当次范围，不在本次写计划时执行。

新题覆盖列表/状态、定位/歧义、测试候选/正文、局部/完整材料、多对象/混合知识来源、闲聊/指代/能力边界。评分要求与新题在运行前冻结，不将 Gold 传给需求模型、执行 Agent 或 reviewer，不随分数修改 Gold。

### 8.3 指标与上线门槛

分别统计需求理解、真实取证、答案支持与原问题覆盖、正确完成、误拒答、无依据完成、审查错批准/错拒绝、恢复效果、阶段失败、实际权限/预算违规、时延和模型用量。工具调用第二层与完整答案质量第三层分别报告，不能把 reviewer 的 accept 当成答案 Gold 或正式端到端验收。

审查输入、结构化输出、来源与提交 hash、版本和 usage 可重放；不保存隐藏推理或凭据。需求、Decision/格式修复、审查及可取得的其他阶段调用分别计量，缺失用量为 null，不伪造零，不改变旧公开 Decision 统计含义。

默认切换须满足：相关回归通过，已知硬违规负例无错误放行；新题正确完成和误拒答有实际改善；严重的伪造来源/越界/未执行测试却宣称通过等新题不得放行；非严重错误完成不高于对照；审查错误和耗时有完整独立复核。样本不足或结果不稳定时继续保持候选，不预先承诺某个通过率。

## 9. 本次明确排除的扩大范围

不做每轮 LLM 审核、不增设自动需求重规划、不重置 5/4/2 原预算、不新增测试执行/写入工具、不重写知识 Planner/检索或前端、不引入新的 stream、记忆压缩、远程项目挂载或第二个 Agent 工作流。后续残留问题先按需求错误、材料能力、提交错误、审查错误和期限失败归因，再决定是否扩展。

评测使用独立 fixture/数据库和工作区内输出目录，不向当前 8000 产品服务发测试请求，不重启该服务。业务身份或材料快照发生变化时停止混合记录并重新冻结；本次只生成可评审方案。
