# 核心任务对象取证切片（设计与落地记录）

入口与有界对象取证已实施；第一项整体任务可靠性仍OPEN。本切片针对 [真实反例](../validation/2026-10-04-core-workflows.md)，减少按文件名搜索正文、猜行号、只读测试导入和遗漏同文件相关定义。没有启用长期Task/Evidence/Execution v2。

## 保留的边界

- 单一Runtime loop、七个只读工具、5次逻辑决策/4次工具调用/2次工具错误。
- 绑定根由系统注入，沿用原Reader路径/文件/秘密文件/尺寸/编码检查；仅解析或读取，不import/exec、不执行测试。
- Legacy默认Reader v2与历史prompt SHA可用；Engineering明确注册同名Reader v4与匹配decision v4，不同时暴露两套Reader。
- 不增加按题放行Guard、pytest答案特例、隐藏预算外取证或第二层Agent。

## 已落地接口

| 目标 | 输入 | 返回与缺口 |
|---|---|---|
| 明确文件 | `path + target.kind=file + start_line` | 从给定行起有界正文，公开截断与续读 |
| 已有搜索位置 | `window`或`definition`目标 | 有界窗口或实际包含该行的Python函数；定义失败明确fallback |
| 具名对象 | `symbols + names`，同文件最多4个 | AST定位方法/函数/模块或类赋值，限定名与独立正文片段；短名歧义/缺失不任意代用 |
| 文件内匹配 | `matching + query` | Python定义名/正文literal匹配后读定义；其他文本读命中窗口，重叠合并；更多匹配/未读内容明确标示 |

互斥target形状由ToolExecutor schema校验，模型不能混用旧line参数和新对象参数。多片段共享120行/8000正文字符、单行300字符，每片段保留真实连续定位，经原Evidence转换/编号/Verifier/API链路。定义元数据按实际AST验证，内容完整性不等于答案正确性。

`find_tests`继续只发现候选；新Reader根据已知名称或文件内标识符取得实际测试定义，返回真实类限定名。不是测试执行或完整依赖/影响分析。变更表单明确路径已有，围绕该文件取得diff和关联测试；仍提交普通问题，Runtime没有专用动作脚本。

初次预计3～5生产模块；实际涉及9个API/Core模块，多数仅是系统装配、共享读取、预算和片段转换，另两处UI入口。新增专门Reader模块保留版本边界，共享旧访问检查和纯AST导航；没有目录大重构。原三项轻量候选均未晋升。

## 验证与剩余项

原六道开发题完整正确1→3，仅各一次；新核心六题4 PASS/2 PARTIAL。长文档的文件内匹配修订实际取得承诺段落；明确变更路径后的真实会话消除一次误拒答，取得diff、实际测试与准确建议命令。54真实请求与失败都归档，没有自动付费重试。

来源片段保真与限定名已核对，离线CI清单/架构和后续局部回归通过。一般自由任务规划、知识/项目来源混淆，以及答案未读分支的错误推断仍有缺口。完整答案必须继续单列审查，不能用completed或引用合法性验收。
