# 正式对照后的证据修复计划

基线：`f44c79a` / `evidence-formal-results-20261011`。依据是 408 次真实运行的原始工具调用、合同和提交审核，不把旧题重跑包装成新的独立验收。原始结果、Gold、评分口径和标签保留。

## 判断与顺序

不是简单的模型能力不足，也不能只给每道失败题加正则。主要接缝是：需求描述的是用户要完成的事，工具返回的是一个范围内的事实，而现有检查把“工具形态、查询文字、definition 字段”当成了事实充分性的唯一条件。

1. **材料判定（本轮实施）**：让工具在同一次安全读取中返回文件内容身份、实际行数和与返回正文相交的 AST 对象信息。材料检查按真实对象与返回范围判定；同一绑定、路径、文件内容版本的连续正文可以共同证明完整范围。定位看实际返回的匹配内容，不要求搜索字符串和合同 query 逐字相等。旧 Reader v4、旧 matcher、structural_v2、semantic_v1 保留；新通路显式选择 Reader v5、matcher v2、structural_v3 / semantic_v2。需求/执行/审核提示词不同时改动，先隔离材料层效果。
2. **需求与审核（下一阶段）**：明确“读取定义”必须是正文；普通文档关键词不能强制成为 Python symbol；解释/比较可以使用已经要求的同一组材料，不自动增加一份正文义务。审核独立核对原请求的每个对象、深度及条件分支。成功的限定范围未找到与读取失败分开建模；diff 的新旧侧如何支持事实必须明确，不能直接把所有 diff 放宽成完整实现证据。需要新 prompt / 合同语义版本与组件对照。
3. **执行与协议（随后）**：已知路径/限定名直接用 Reader 的 symbols，避免 literal 搜索限定名浪费预算。工具失败后的有限恢复与成功后的无效重复分别设计；Decision / review 非法输出保留技术失败，增加明确的协议诊断与有界修复，不伪装为普通拒答。涉及 Runtime 重复保护时单独版本和回归。

## 第一步的边界

- 不增加证据类别，不让 LLM 发放 E-ID。新增的是程序产生、随原正文记录的来源元数据。
- Reader 仍只读一个允许文件，复用原路径权限、文件大小、120 行 / 8000 字符、单行 300 字符限制；索引只说明对象位置，未返回的正文不算已读取。
- 同一文件的不同内容 SHA、不同绑定、不同路径不能拼接；间隙、裁剪行、模糊短名、重复定义、导入命中不能证明完整对象。续读本身不完整，只有实际连续范围覆盖才完整。
- 局部内容与完整实现分开判定。short name 仅在该文件 AST 唯一解析时可匹配限定名；文档 symbol、跨文件歧义和任意语义相似不由本轮 matcher 猜测。
- 定位材料仍是位置候选：literal 搜索支持实际返回的短名位置，不单独证明所属类；真实 Reader 歧义候选可以支持“有哪些候选位置”，不能用某一个正文替代明确对象。所属关系与“选哪个对象”继续由真实定义材料及语义审核核对。
- 语义审核仍必须通过；引用存在、真实范围、工具白名单、5 次 Decision / 4 次工具 / 2 次错误 / 60 秒、最多 2 次审核保持。
- 默认配置仍为 `rule/legacy/legacy`。第一步不会修复需求漏项、diff 替代支持、成功否定查找或 JSON 格式失败，结果单独标明这些剩余问题。

## 验证与发布

1. 零模型回归：完整文件包含定义、局部窗口关联定义、唯一短名与限定名、完整多页正文；反例覆盖同名/重复/导入、内容版本变化、不同绑定/路径、范围有洞、单行裁剪、未知引用、只引用部分续读、文件读取失败及既有取消/预算边界。
2. 固定旧合同与实际工具调用做组件复核，输出新记录并保留原 SHA；新 Reader 正文必须与旧记录相同才能归因于元数据判定，不覆盖原实验结果。这只是开发诊断，不是新的模型验收。
3. 冻结新提交后，用当前产品装配执行 D（旧材料）与 D2（新材料）的已知题回归，预算、提示词和评分器一致。自然模型合同仍可能不同，不宣称纯因果消融；新题 24 道已知，仍叫回归。原始失败全部保留。
4. 完成相应离线检查、本地 CI 检查、提交/推送并核对远端流水线。第一步达标后再进入第二步；不会为了凑通过率更改 Gold、增加预算或直接切默认。

## 第二步具体实施顺序

1. **先修需求解释**：版本化新 prompt，单独验证“任务”与“答复约束”的区分。拒绝编造、不要运行测试、不可读时说明原因，是行为约束；只有用户确实要求当前工具不能执行的操作才产生 unsupported。显式读取定义、正文、完整函数不得规划成 locator。解释/对比依赖已经要求的事实，不自动产生第三份材料目标。优先复核 dev-037、val-117、dev-017/020，但回归覆盖同类新表达，不能按题号分支。
2. **补齐范围表达**：现有 full_range + 空 symbol 无法可靠区分完整定义与完整文件。新合同须能明确目标范围是文件、对象或指定行段；未知具名对象可由实际 Reader 的唯一对象定位后确认，不能凭“一个完整文件”代替未知的默认值定义。只有新增字段/语义确实需要时建立新合同 schema 与专用解析，不在旧 v2 schema 下偷偷改变含义；旧合同、provider、matcher和结果标签保留。
3. **区分读取与事实支持**：用户要读正文，仍需要真实正文覆盖；用户只问 patch 改了什么，实际同路径/模式/版本的 diff 可支持其中可见的前后事实，不额外强制当前正文。完整实现、测试执行或未显示的事实不允许从 patch 推断。允许的材料来源/形态来自固定能力清单，不由模型创造新类型、E-ID、权限或预算。
4. **表达条件分支**：成功查找但未找到是限定范围内的真实工具事实；读取失败是实际失败诊断，不能给正文 E-ID。合同和审核分别表达这些允许的结果；只在原请求允许这种条件结论时完成调查，不把任意空搜索变成全仓不存在或任意失败当作完成任务。
5. **审核对原请求独立验收**：专门核对对象、正文读取义务、范围、条件分支和答案中的具体解释。误规划仍判合同问题；非法 unsupported/fulfilled 组合仍判协议失败。增加遗漏正文、错误分支解释、正确缺文件拒答等审核组件对照，真实模型审查结果单独记准确性，不使用自身 accept 充当评测分数。

第二步验收须分别报告需求忠实度、固定材料/固定答案的审核结果和真实工具成绩。当前96题均为已知回归；冻结未用于调试的新表达题，并说明开发助手编题的限制。5/4/2和审核2次保持；第三步的重复失败恢复另开检查点，不与合同修复混跑。
