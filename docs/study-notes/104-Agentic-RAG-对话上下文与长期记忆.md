# Agentic RAG 对话上下文与长期记忆

多轮对话需要把当前问题和一部分近期会话交给 Agent。系统先保留有界的最近消息，再把追问解析成可以独立检索的 standalone query；没有历史时直接沿用单轮问题。

最近窗口不是无限拼接：本实现最多保留 6 条消息，并使用 1200 token 的上下文预算。选择从最新消息向前进行，保留原始角色和顺序；超出预算时淘汰更旧的消息，单条过长的最新消息按 token 截取其末尾。这个过程确定、不摘要，也不把当前问题计入历史预算。

解析后的 query 仍然必须经过正常的 Planner、Retriever、Verifier 和答案生成。历史只是帮助理解指代，不是 RAG 证据；可靠答案仍以检索到的工程或知识库证据为准。解析器最多调用一次，失败时回退到当前问题，并只记录安全的 fallback warning。

长期记忆是另一种能力，通常需要持久化、身份边界、更新策略、遗忘和隐私控制。把无限历史不断拼进 prompt 既没有稳定预算，也没有这些边界，因此不能作为有效的长期记忆策略。

## 为什么要做 A/B

Context 代码存在，不等于多轮能力有效。把同一轮追问分别作为 no-history 与 with-history 请求，并复用真实的上一轮答案，才能观察指代理解、检索相关性和主题切换是否真的改善；若只看单次 with-history 结果，就无法区分上下文收益、基础 RAG 波动和模型偶然性。
